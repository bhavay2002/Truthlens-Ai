## 4. ⚠️ Incorrect Multi-task Optimization Behavior

**Problem:**  
Loss is only calculated for whichever heads are present in the batch (e.g., ideology only, emotion only).  
**Result:** Shared encoder is not trained jointly for all tasks—gradients only reflect the present task(s) and shared features may diverge or become under-optimized.

**How to Fix:**
- **Batch Construction:** Try to sample batches with at least one valid label for *all* (or at least most) tasks in each batch. If this isn’t feasible (due to label coverage limits), consider partial updates (see below).
- **Partial Loss Update (Best Practice):**  
  - For each batch, compute the loss for all tasks, but **mask** the NA labels within each task head’s loss.
  - Average (or dynamically weight) the total loss across all tasks—not just the ones represented in the batch.
  - **DON’T** just skip missing tasks; instead, compute "zero" loss for missing labels, so their weights stay balanced in the optimization.  
- **Example (PyTorch):**
    ```python name=multi_task_loss.py
    total_loss = 0
    num_tasks = 0
    for task in tasks:
        if task.has_valid_labels(batch):
            total_loss += task.loss(batch)
        else:
            # Optionally, add zero to total_loss or just increment num_tasks
            pass
        num_tasks += 1
    total_loss = total_loss / num_tasks
    ```

## 5. ⚠️ Massive Data Leakage Prevention = Data Loss

**Problem:**

- **Effect:** Class/task distributions may be skewed even further, worsening sparsity. Validation/test may no longer align with train distribution.

**How to Fix:**
- **Re-balance Training Set:**  
  - After cleaning, re-analyze task label distributions.
  - If feasible, re-weight, upsample, or synthesize data for tasks/classes that are now badly underrepresented.
- **Audit Distribution:**  
  - Plot the post-cleaning label histograms for each task and compare them to pre-cleaning.
- **Iterative Clean/Balance:**  
  - If you must drop more data, balance again afterwards (class weighting, stratified sampling, etc).

## 6. ⚠️ NA Handling Strategy is Likely Wrong

**Problem:**  
You’re skipping/masking NA labels; thus, the set of active tasks per batch varies wildly.
- Creates unstable, inconsistent shared updates.
- Encourages some heads to dominate if their examples are more common.

**How to Fix:**  
**Batch + Loss Strategy:**
- **Ensure every mini-batch includes samples for all tasks (stratified or multi-task batch sampling) when possible.**
    - Or, progressively fill smaller "task-batch" buffers and only update when all are non-empty.
- **Dynamic Loss/Gradient Normalization:**
    - Use GradNorm, DWA, or uncertainty-based loss scaling to adaptively keep task contributions balanced, even if some tasks are sparser.

**Batch Sampler Example:**
```python name=batch_sampler.py
# Pseudocode: Ensures each batch has at least one label for each task.
batches = []
while not done:
    batch = []
    for task in tasks:
        sample = sample_from_task(task)
        if sample:
            batch.append(sample)
    batches.append(collate(batch))
```
