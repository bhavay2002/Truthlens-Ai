This one is deceptively dangerous. A `DtypeWarning: Columns have mixed types` in your data layer means **your feature space is not well-defined**—and that propagates into tokenization, batching, and ultimately model behavior.

Let’s fix it at the **data contract + ingestion + validation** levels so it never recurs.

---

# 🔴 What’s Actually Happening

`pandas` is inferring column types on the fly. If a column contains mixed primitives:

* `"1", "2", "unknown"` → becomes `object`
* `0, 1, "0"` → mixed int/str
* `True, "False"` → inconsistent boolean encoding

Then downstream:

* tokenizer sees inconsistent input types
* labels may be cast incorrectly (`"1"` vs `1`)
* loss functions receive invalid tensors
* worst case: **no crash, just degraded training**

---

# ✅ Fix Strategy (3 Layers)

## 1️⃣ Define a **Strict Dataset Schema (Single Source of Truth)**

Do **not** rely on inference. Define explicitly:

```python
DATA_SCHEMA = {
    "text": "string",
    "bias_label": "int64",
    "toxicity_label": "int64",
}
```

If you have optional fields, still define them.

---

## 2️⃣ Enforce Types at Load Time

```python
import pandas as pd

def load_dataset(path):
    df = pd.read_csv(
        path,
        dtype={
            "text": "string",
            "bias_label": "Int64",   # nullable int
            "toxicity_label": "Int64",
        },
        keep_default_na=True,
        na_values=["", "NA", "null", "None"]
    )

    return df
```

⚠️ Use `"Int64"` (capital I) for nullable integers—not `int64`.

---

## 3️⃣ Hard Validation (Fail-Fast)

```python
def validate_dataset(df):
    assert df["text"].map(type).eq(str).all(), "Non-string text detected"

    for col in ["bias_label", "toxicity_label"]:
        if not pd.api.types.is_integer_dtype(df[col]):
            raise RuntimeError(f"{col} is not integer dtype")

        if df[col].isna().any():
            raise RuntimeError(f"{col} contains NaNs")

        if not df[col].isin([0, 1]).all():
            raise RuntimeError(f"{col} contains invalid labels")
```

# 🔧 Cleaning Mixed-Type Columns (One-Time Repair)

If your dataset is already corrupted:

```python
def clean_labels(df):
    df["bias_label"] = (
        df["bias_label"]
        .astype(str)
        .str.strip()
        .replace({"true": "1", "false": "0"})
    )

    df["bias_label"] = pd.to_numeric(df["bias_label"], errors="raise")
    return df
```

⚠️ Use `errors="raise"` — never `"coerce"` (it hides errors).

# 🧱 PyTorch Dataset Layer (Enforce Final Types)

```python
class TruthDataset(torch.utils.data.Dataset):
    def __init__(self, df, tokenizer):
        self.texts = df["text"].tolist()
        self.bias = df["bias_label"].astype(int).tolist()

    def __getitem__(self, idx):
        encoding = tokenizer(self.texts[idx], truncation=True, padding="max_length")

        return {
            "input_ids": torch.tensor(encoding["input_ids"]),
            "attention_mask": torch.tensor(encoding["attention_mask"]),
            "bias_label": torch.tensor(self.bias[idx], dtype=torch.long),
        }
```

* ❌ Allow `object` dtype in training pipeline
* ❌ Cast everything blindly with `.astype(int)` without cleaning
