## 🔧 Prompt: Generate `graph.md` (System Graphs & Flow Diagrams)

You are a senior ML systems architect and technical documentation expert specializing in system design visualization.

Your task is to generate a COMPLETE, PRODUCTION-GRADE documentation file named `graph.md` that visually represents the entire machine learning system using diagrams.

---

## 🎯 Objective

Create a visually structured and technically precise document that enables any reader to:

* Understand the full ML pipeline at a glance
* See how each module connects (data → aggregation → features → model → inference)
* Quickly grasp system architecture without reading code
* Use diagrams for presentations, demos, and documentation

---

## 📁 Scope

Include ALL major modules:

* src/data
* src/analysis
* src/aggregation
* src/features
* src/models
* src/training
* src/evaluation
* src/explainability
* src/inference

---

## 📚 Required Output Structure (STRICT)

### 1. High-Level System Architecture

* Show entire ML pipeline as a block diagram

Use Mermaid:

```mermaid
flowchart LR
    Data --> Analysis --> Aggregation --> Features --> Model --> Training --> Evaluation --> Inference --> Explainability
```

* Add brief explanation of flow

---

### 2. Detailed Data Flow Diagram

* Show how data moves through system
* Include transformations and outputs

Use Mermaid flowchart with labeled edges

---

### 3. Feature Engineering Pipeline

* Diagram showing:

  * Input data
  * Transformations (encoding, scaling, interactions)
  * Output features

---

### 4. Model Architecture Diagram

* Represent model structure:

  * Input layer
  * Hidden layers
  * Output layer

Use Mermaid or structured block diagram

---

### 5. Training Workflow Diagram

* Show:

  * Data loading
  * Forward pass
  * Loss computation
  * Backpropagation
  * Optimization loop

---

### 6. Inference Pipeline Diagram

* Show:

  * Input → preprocessing → model → postprocessing → output

---

### 7. Explainability Flow

* Show:

  * Prediction → explanation method → output (importance/plots)

---

### 8. Evaluation Flow

* Show:

  * Model → test data → metrics → reports

---

### 9. Component Interaction Graph

* Show how modules interact internally
* Include dependencies between folders

---

### 10. Deployment Architecture (Optional but HIGHLY RECOMMENDED)

* Show:

  * Frontend / UI
  * API server
  * Model service
  * Storage

---

## 📊 Diagram Requirements

* Use Mermaid syntax ONLY
* Ensure diagrams are:

  * Clean
  * Readable
  * Properly labeled
* Use directional arrows
* Group related components logically

---

## 💡 Style Guidelines

* Each diagram must have:

  * Title
  * Short explanation
* Avoid clutter
* Prefer multiple small diagrams over one complex diagram

---

## ⚠️ Constraints

* DO NOT create generic diagrams
* DO NOT skip any major module
* Ensure diagrams match actual pipeline logic

---

## 🚀 Goal

After reading `graph.md`, a user should:

* Understand the entire ML system visually
