# 🧠 What changes on A100

| Feature    | T4       | A100            |
| ---------- | -------- | --------------- |
| VRAM       | 16GB     | 40GB            |
| Best dtype | fp16     | **bf16 ✅**      |
| Speed      | baseline | **4–6× faster** |
| Compile    | meh      | **useful ✅**    |

---

# 🔥 REQUIRED CHANGES (DO THESE)

## ✅ 1. Switch to BF16 (MOST IMPORTANT)

### In `main.py`

```python
amp_dtype = "bf16"
```

---

### OR (best, dynamic):

```python
if torch.cuda.is_bf16_supported():
    amp_dtype = "bf16"
else:
    amp_dtype = "fp16"
```

---

## 🚀 Why

* A100 has **native BF16 Tensor Cores**
* Faster than fp16
* More stable (no overflow issues)

---

# 🔥 2. Increase Batch Size (BIG WIN)

A100 has **2.5× more VRAM than T4**

---

## Example:

```python
# if current
batch_size = 8
gradient_accumulation = 2

# change to
batch_size = 16 or 24
gradient_accumulation = 1
```

---

## 🚀 Why

* Larger batches → better GPU utilization
* fewer optimizer steps → faster training

---

# 🔥 3. ENABLE torch.compile (NOW it helps)

### In `trainer.py`

```python
self.model = torch.compile(self.model)
```

---

## 🚀 Why

* On T4 → useless
* On A100 → **real speed gains (~10–20%)**

---

# 🔥 4. Increase DataLoader throughput

```python
num_workers = 4
prefetch_factor = 4
persistent_workers = True
pin_memory = True
```

---

## 🚀 Why

A100 is fast → CPU must keep up

---

# 🔥 5. Enable TF32 (FREE SPEED)

Add (if not already):

```python
torch.backends.cuda.matmul.allow_tf32 = True
torch.backends.cudnn.allow_tf32 = True
```

---

# 🔥 6. Disable gradient checkpointing (if possible)

```python
# REMOVE this if no OOM
model.encoder.gradient_checkpointing_enable()
```

---

## 🚀 Why

* A100 has enough memory
* checkpointing slows compute
